# CP-004 — папки словарей

## Использование

В разделе «Словари» папка выделена спокойным зелёным фоном. Основная область
открывает отдельный уровень; стрелка справа показывает только непосредственных
детей, без автоматического рекурсивного раскрытия. Несколько Preview могут быть
открыты одновременно. Закрытый Preview скрыт и inert, его кнопки удаляются.

Checkbox выбирает объект, не открывая его. Верхняя панель: Up / Down / Move /
Subfolder / Rename / Delete. Выделение ограничено одним уровнем. Move принимает
несколько папок и словарей одновременно; Destination Browser позволяет войти в
папку, вернуться и выбрать корень. Собственные потомки и текущий родитель
недоступны как назначение. После успеха выделение очищается.

Кнопки добавления создают папку или словарь в текущем уровне. Rename меняет
название и необязательное описание. Путь Folder Stack строится по стабильным ID,
в URL хранится только `df`; Back/Forward и reload восстанавливают уровень.
История содержит SHA-256 идентификатор владельца, не access token. Перемещение
или удаление открытого уровня извне приводит к безопасному возврату в корень.

Удаление дерева папок предварительно показывает число папок и сохраняемых
словарей. Подтверждение удаляет **только папки**, все словари из их поддеревьев
возвращаются в корень с прежними ID, словами и карточками. Изменение структуры
после Preview требует новой проверки. Для удаления самих словарей действует
прежняя отдельная функция с подтверждением каждого словаря. Смешанное удаление
папок и словарей намеренно недоступно; смешанный перенос поддерживается атомарно.

## Данные и API

Миграция `0003_dictionary_folders.sql` только добавляет таблицы и индексы.
Существующая таблица dictionaries и строки карточек не переписываются:

- `dictionary_folders`: ID, владелец, parent_folder_id, title, description,
  position и даты. Composite FK требует того же владельца у родителя.
- `dictionary_locations`: отдельная связь dictionary_id → folder_id/position.
  Отсутствующая связь или NULL folder_id означает корень. Поэтому старые REST
  и MCP create_dictionary продолжают создавать словари в корне без изменения
  своих контрактов. Удаление словаря прежним API удаляет только его placement
  через FK, папку не затрагивает.
- `dictionary_tree_operations`: идемпотентные receipts по owner/request_id.
- `dictionary_folder_confirmations`: одноразовая проверка состава дерева,
  привязанная к владельцу, snapshot и сроку пять минут.

`GET /api/dictionary-tree` возвращает только структуру владельца, метаданные
словарей, число слов и version. POST принимает action, request_id и
expected_version; actions: create_folder, create_dictionary, rename, move,
reorder, delete_preview, delete_confirm. Авторизация — прежний access token,
общая серверная проверка владельца. Новых MCP tools нет.

Изменение выполняется одной D1 batch transaction. Первое условное INSERT
проверяет актуальный snapshot; все последующие SQL защищены nonce этой операции.
При конкурентном изменении возвращается 409 без частичного переноса. Повтор
request_id с тем же намерением возвращает прежний результат, с другим — 409.
Проверки циклов, владельца, соседства и назначения повторены на сервере.
Обновление позиций использует bulk SQL, не отдельный запрос на каждого соседа.
Порядок общий для папок и словарей; равные позиции разрешаются датой и ID.

Содержимое слов не входит в organizational snapshot: появление нового слова не
блокирует перенос папки. Состав папок/словарей и их placement входит полностью.
Folder Delete никогда не выполняет DELETE dictionary_words/dictionaries.
Существующее удаление самого словаря считает `DELETE ... RETURNING id`, а не
общий D1 meta.changes: каскадное удаление placement не увеличивает число
удалённых словарей в REST/MCP ответе. Контракт deleted остаётся прежним.
Таблицы Inbox не участвуют. Публичные ссылки продолжают использовать прежний ID.

## Frontend и безопасность кэша

Новая логика выделена в `dictionary-tree-model.js`, `dictionary-tree.js` и
изолированный `dictionary-tree.css`; app.js содержит узкий adapter к прежнему
рендерингу словарей и трёх панелей. Глубина не увеличивает отступы Full Folder.
Новая схема не меняет AI pipeline и meta.fullCard.

Организация загружается с сервера, не восстанавливается из старого кэша.
Старый усечённый token cache key заменён полным owner-specific ключом v2:
токены с одинаковым длинным префиксом больше не разделяют кэш. Старый кэш
не импортируется в облако автоматически, включая случай пустого REST ответа.
Облачные данные остаются источником истины. При смене токена сбрасываются
папка, выделение, dialogs и pending reads; запоздалый ответ старого владельца
игнорируется. Секретные cache keys не выводятся в отчёты.

Организационные операции требуют сети. При ошибке доступен Refresh/retry,
не производится перезапись дерева локальным снимком. Повтор отправки формы
после потерянного ответа использует прежний request_id. Двойное нажатие не
отправляет два запроса. Старые offline-кэши до v2 могут потребовать первого
успешного online чтения; это не удаляет данные D1.

PWA build включает новые модули; API/авторизованные ответы не добавляются в
Service Worker cache. Новая версия активируется прежней кнопкой Update.
Production-проверка обнаружила HTTP 308 `index.html → /` на существующем
Cloudflare Pages. Установщик теперь читает HTML напрямую из корня, проверяет
прежний точный SHA-256 и сохраняет под прежним index.html cache key. Произвольные
редиректы всё ещё отклоняются. Регрессия A→B дополнена этим поведением Pages.

## Проверки

- `npm run test:dictionary-folders`: реальный Worker/Miniflare/D1 на synthetic
  fixtures; additive migration и сохранение fullCard, корень старых словарей,
  40 уровней, cycles, owner isolation, групповые переносы, порядок/переименование,
  идемпотентность, конкуренция, stale confirmation и safe folder deletion.
- `npm run test:dictionary-folders-ui`: Chrome 390×844, 844×390, 1366×900;
  Preview/Full Folder/history/reload, отдельное выделение, верхняя панель,
  Destination Browser/корень, долгий ответ/двойное нажатие/потерянный ответ,
  длинное название, смена владельца при pending запросе, реальные synthetic
  Inbox данные, публичный словарь и отображение трёх панелей.
- Регрессия: test:mcp, test:full-cards, test:oauth-browser, test:pwa;
  frontend build/check и JavaScript syntax.
- Production: backup восстанавливается локально, сравниваются хеши **всех
  прежних таблиц** до/после миграции; существующий Worker совместим с additive
  DDL. Smoke — только чтение дерева/REST/MCP и временный OAuth grant с отзывом,
  без создания/удаления пользовательских словарей.

Размеры iPhone в Chrome — эмуляция viewport, не физический iPhone и не Safari.
На телефоне после Update проверить два сайта: стрелку/вход/checkbox, Move и
возврат в корень, Back/Forward, поворот экрана, смену access token. Создавать
и удалять для ручной проверки только собственную временную пустую папку;
пользовательские словари удалять для проверки не требуется.
